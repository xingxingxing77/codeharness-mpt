### 目标结构
| 角色 | Redis 结构 | 为什么 |
|---|---|---|
| 会话态（N1 加 `user_id`） | `HASH ch:sess:{sid}` 字段级 HSET + `ZSET ch:index` | 消灭全量重写;HSET 部分更新天然并发安全 |
| 事件流 | **Streams** `XADD ch:ev:{sid} MAXLEN ~5000`;补历史 `XRANGE (seq`,续推 `XREAD BLOCK` | **不用 Pub/Sub**:无持久化、慢消费者丢事件,`after=seq` 兑现不了。Stream entry id 单调即 seq |
| 插话队列 | `LIST ch:chat:{sid}` RPUSH/LPOP | 投递方与图循环可能不同 worker;`route` 的 drain 逻辑不动 |
| checkpointer | `langgraph-checkpoint-redis`(`use_json=True` + TTL) | 接缝就是 `checkpointer=None` 那一行 |
| 控制通道 | `PUBLISH ch:ctl:{sid}`(stop/restart) | 替代 `t.cancel()` |
| 限流（N5 拆分后保留的一半） | `INCR` + `EXPIRE` 固定窗,key=(user_id, model, window) | 多 worker 共享**请求数/并发**配额,进程内计数器失效。⚠ 做的是限流,**不是金额预算**——超限在 HTTP 入口 429,不进图、不在内核判 |
| 用量快照（只读） | `HASH ch:cost:{sid}` 字段 `pt/ct/total_cost/round` | 供前端与 N4 trace 面板读；**没有任何代码读它来决定是否继续跑** |
| trace（N4） | `ZSET ch:trace:{sid}` + 每节点 span JSON | 出 P95 与 token 归因 |

### 本步唯一的硬工程点：sync → async 桥
内核报道槽是**同步** callable(`server/runner.py:75` 注释写着"普通函数(桥接铁律)"),Redis 写入是异步。**不能改成 `await XADD`**——那会迫使内核全链路 async 化,污染 `report.py` 与所有 Action。

正解:server 侧加桥——**有界 ring buffer + 后台 flusher task**,同步 `publish` 只入队,flusher 批量 `XADD`。⚠ `XADD` 返回的 stream id **必须回写事件 payload**,让 `seq` 由服务端承接,内核 `report.py` 零改动。
