## 背景
C12 分桶落地后一直挂着半格：「同场混两种币价」缺正向读数，理由是「要第二个已计价 provider」。
用户提案是撤成 ⛔ 带理由；我上一轮也推荐 ⛔。**两个方案都不必要**。
`t8_two_currency_buckets` 喂的是构造好的 `AIMessage`，它证口径不证「真跑一次调用之后两桶各有数」——
缺的从来不是厂商，是**真回执**，而本机桩就是真端点（走真 HTTP、真 SDK 解析、真 usage 字段）。

## 决策
起**三台本机 OpenAI 兼容桩**（端口取 0；model 名分别落在价表的 USD 行 / CNY 行 / 另一台同 USD 行做对照），
经真 `LLMGateway.ainvoke` 把回执打进**同一个 CostManager**。新增 `tests/s8_runner_meter.py::t9`（8→9 组）：
两桶各对价表、逐笔 `records[].cc` 分列 USD/CNY、快照两桶都在且无 `total_cost`；
对照组证明币种是**按回执里的 model 真算的**（两台都回 USD 行名字时 CNY 保持 0）。
反向验证 3 例全 CAUGHT（币种写死 USD → 红「USD 桶对不上价表」；逐笔不记 cc → 红；快照加回 total_cost → 红）。

## 后果
正面：那半格不再挂 ⬜ 也不再需要 ⛔；不花钱、不引外部数据源、不依赖第二个厂商账号。
仍缺的（诚实边界）：**真厂商的 usage 字段差异**（少字段、不回、命名不同）未证。
重开条件：接入任何新厂商时，补一发真端点读数进 C12 行，别拿桩冒充。
