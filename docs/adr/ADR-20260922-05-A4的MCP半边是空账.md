## 状态
已接受（判为无出处，撤账）

## 背景
`plan/PLAN.md §7` 挂着半句「A4 的 MCP 半边（本机没有可连的 MCP server）」，我上一轮据此把
「要不要造个本地 MCP server」列成待拍项。取证结果：**这条没有判据实体**——
`§2 A4 行`三格全文 grep `MCP` 命中 0；`codeharness/` 与 `server/` 里 `mcp` 实现面 0（只有 `vendor/ponytail` 的 benchmark）；
而 `§6:327` 明确列的 ⛔ 是**前端「MCP 面板」**。也就是说：一句挂在 A4 名下的括号注释，被后续会话当成了一个待办。

## 决策
**从 §7 删掉这半句**，并把「两件半的外条件」改准为「一件半」（C12 那半已由 ADR-04 闭掉）。
澄清两条，写进文档免得再漂：① §6 的 ⛔ 指的是**前端 MCP 面板**，不是「MCP 工具接入已规划」；
② Qoder 平台自带的 MCP 连接器不是本产品能力，别混为一谈。
重开条件：真要接 MCP 工具，**先立判据**（接哪个 server、审批门怎么过、无 function calling 的网关怎么接），
而不是引用今天删掉的这句话。

## 后果
正面：账面少一格永远取不到读数的空账；下一棒不再照 §7 去找 A4 的 MCP 判据。
负面：若这半句其实指向某件有出处的活（用户手误之外的来源），删掉后要靠本 ADR 的背景段找回——已把取证三条写全。
