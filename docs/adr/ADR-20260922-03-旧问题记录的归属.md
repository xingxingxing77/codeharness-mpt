## 状态
已接受（与提案不同：不删、不改名、不搬目录）

## 背景
仓库根 `log日志/` 三篇未跟踪笔记（`1-langfuse-log.md`、`2-langfuse-log.md`、`max_token阈值问题.md`）。
提案是「只留第三篇并改成英文名、删两篇 Langfuse 旧记录」。核实结果：
`max_token阈值问题.md` **被 PLAN §4 C17 行末正引用着**（那族「截断→repair 重试整段重烧」的账本形状就是从中来的）；
另两篇是本仓接入 Langfuse 之前的实测记录，而 Langfuse 已在场（`tests/s9_langfuse.py`）。
另有一条实事故在先例里：没进仓的治理总文档曾被 `git clean -fdx` 整条抹掉（PLAN §1 记过）。

## 决策
**三篇全部进仓，保持原路径与中文文件名**（`git add log日志/`）。
不删（零引用 ≠ 无价值，删除不可逆）、不改名（改了就把 C17 那条引用指针剪断）、不新建 `docs/troubleshooting/`
（`docs/` 现有命名全是中文体系：`判定-*`、`对照1-*`、`施工1-*`，为三篇旧笔记破例是制造第二套规范）。

## 后果
正面：`git clean -fdx` 不再能抹掉它们；引用指针全部继续有效；diff 最小。
负面：根目录多一个中文名目录被跟踪——观感问题，不是数据问题。要治观感应该是**整仓定一次命名规范**，
而不是就地造例外。
