## 1 · 模块职责与边界

Vue 3 + Vite + pinia，无 router（单页壳层用 `App.vue` 条件渲染登录页／主帧）、无 i18n、无 UI 库、无 tailwind，零新增前端依赖。整个前端是后端 FastAPI 服务（`server/**`）的**观测与控制面**：会话列表、SSE 事件流的实时合成、审批／插话／目标等 takeover 交互、工作区文件与知识库摄取、时间旅行回放、用量账目。

前端与后端的**契约面**分三层，各有机器判据（见 §5）：

1. **HTTP 传输层**（`api/client.ts`）：唯一 `fetch` 出口，统一 Bearer 头、请求 deadline、401 清票、FastAPI `detail` 摊平。
2. **信封与事件层**（`types.ts::WEvent` + `stores/sessions.ts::applyEvent`）：SSE 每条事件的 `{kind, block, uuid, name, value, cursor, seq, ts, role}` 形状，及后端 `BlockType` 词汇表 ↔ 前端分发的逐值对齐。
3. **路由层**（`api/client.ts::api.*` 的每个模板串）：前端消费的 `/api/...` 路径必须 ≡ 后端注册的路由（`s8 t3` 反查「前端消费了一条后端没有的路由」）。

`api/` 与 `stores/` 的边界：`api/client.ts` 只管「怎么发、怎么把 HTTP 结果翻成 Error」，**不持状态**；`stores/*` 持状态并编排调用。`stores/sessions.ts` 是唯一直接 `new EventSource` 的地方（`fetch` 之外唯一的原生连接），它绕开 `req()` 走查询参数带票（EventSource 发不了 header）。其余 store（auth/settings/theme/toast/layout/columns/workspaceView/ui）各自只管一块纯状态，除 sessions/auth 外都不碰网络。

🟡 **网络冗余：右栏每次切页签都重拉文件树与编排图**
`DetailsPanel.vue:440` `watch(() => [store.currentId, ui.rightView], load)`，而 `:314` 的 `load()` 每次都 `Promise.all([api.fileTree(sid), api.sessionGraph(sid)])`。

**为什么**：`watch` 数组源任一元素变化就回调 ⇒ 光是**切页签**（cards↔inspect↔review↔trace↔replay，`ui.rightView` 变）也会重新发一次 `fileTree`+`sessionGraph`。本文件 `:383` 自己的注释就写着 `/graph` 实测约 2.2s——`doUploadKb` 特意在它返回前先解锁「摄取中…」以免替这 2.2s 背锅。于是一次会话里点几次右侧页签，就叠几发 2.2s 的图重建 + 整树扫描，而这些数据只随会话变，不随页签变。参照 `pick()`（`:303`）对 trace/replay 已经做了「切走再回不重复请求」的本地游标缓存，`load` 却没这层。

**建议**：把 `fileTree`+`sessionGraph` 的重拉门控到 `currentId` 变化（拆成 `watch(currentId, load)` + 仅在确实改了树的动作（doImport/doUploadKb/doRemoveKb）里手动 `load()`），页签切换不触发。

🟡 **信任边界：SSE 与工作区图片把 Bearer 票放进 URL 查询串**
`sessions.ts:360-362` `const authQ = tok ? '&access_token='+... : ''` → `new EventSource('/api/sessions/${sid}/events?after=${after}${authQ}')`；同类 `sessions.ts:698` `workspaceUrl()` 返回 `/workspace/${rel}?access_token=${token}` 供 `<img>`/预览。

**为什么**：EventSource 与 `<img>` 发不了 `Authorization` header，代码用查询参数带票是已知取舍（`sessions.ts:358` 注释也点名）。但票进 URL 意味着它**会落进服务端/nginx 访问日志的完整请求行**，也进不了 `NO_PROXY` 之外的 Referer 隔离。auth 默认关（`health.auth_enabled` 假）时不显形，但 `PLATFORM__AUTH_ENABLED=1` 的部署里，长驻 SSE 连接的票就在每一行 access log 里。

**建议**：属已知约束，先**确认票的生命周期与可撤销性**（能否短 TTL / 独立只读票 / 服务器重启丢表），并把这条写进未验边界由有 auth 的活体验一次；不建议前端自造 header 包装器（EventSource 无该能力，Fetch+ReadableStream 才是升级路）。

🟡 **无障碍：设置页的开关/单选控件对键盘与读屏器不可达**
`Toggle.vue:2` `<button class="tog" @click="$emit('update:modelValue',!modelValue)">`（无 `role="switch"`、无 `aria-checked`、无可访问名）；`RadioCards.vue:3-9` 可选项是 `@click` 的 `<div>`（无 `role="radio"`/`aria-checked`、无 `tabindex`）。

**为什么**：这两个是**全部设置分节**的控件底座（GeneralPage 十几个 `Toggle`、AppearancePage 主题 `RadioCards` 等）。读屏器只听到一个无名按钮、报不出开/关态；`RadioCards` 整组不能用键盘选。视觉用户靠 `class="on"` 的色差区分，但 AT 用户拿不到「当前值」。这与本仓其它地方（`VButton`/`FoldToggle`/`VStateDot`/`UsagePage` 行都补了 role/tabindex/aria）的用心不一致。

**建议**：`Toggle` 根加 `role="switch"` `:aria-checked="modelValue"` + 由 `Row` 传 `aria-label`（或 `Row` 的标题即其名）；`RadioCards` 用 `role="radiogroup"`/`role="radio"` + `tabindex` + 方向键（可复用 `VMenu.vue:104` move 的写法）。属零依赖纯属性改动。

🟡 **无障碍：会话行/项目行的操作钮只有 `:hover` 才存在，键盘永远点不到**
`SessionRow.vue:260` `.rowActions{display:none}` → `:267` `.sessionRow:hover .rowActions{display:inline-flex}`；`ProjectRow.vue:114/122` 同款（「⋯ 会话操作」与「+ 新建会话」）。

**为什么**：`display:none` 会把子元素**移出 tab 序与无障碍树**，`:hover` 只对指针成立，没有 `:focus-within` 变体 ⇒ 纯键盘用户既无法聚焦也无法显示重命名/归档/置顶/删除，或组内新建会话；`SessionRow` 根只有 `role="treeitem"` 也没有 `tabindex`，无法聚焦。这是「交互入口对鼠标之外不存在」的一族。对照 `ChatNode.vue` 的 `inspectPill` 用了 `opacity:0` + `:focus-visible` 双通道（正确做法）。

**建议**：`.rowActions` 增加 `.sessionRow:focus-within .rowActions{display:inline-flex}`（并把行设 `tabindex="0"`/`role` 与 `aria-activedescendant` 对齐树语义）；或改 `opacity`+`visibility` 而非 `display`，让焦点可达。

🟡 **待确认：权限/记忆/语气类开关是纯 localStorage、无后端效果，而文案声明了安全关键行为**
`settings.ts:5` `defaults` 里 `defaultPermission/autoReview/fullAccess`、`GeneralPage.vue:20-25` 的「完全访问权限：无需你批准，即可编辑你电脑上的任何文件并运行联网命令」、`PersonalizePage.vue:20-30` `memoryEnabled`、`p.tone/instructions` 等——只 `persist()` 进 localStorage，无任何 `api.*` 消费（本面 grep 现证：设置页零 `api.` 调用）。

💭 **死代码 + 误导注释：`useFollowScroll` 内的 `onScroll` 从未被注册**

💭 **资源：`resetStream` 只清引用不取消已排的 rAF/定时器（自愈，无正确性后果）**

💭 **一致性：`VMenu.move()` 的 `next===-1` 分支恒不成立**
`VMenu.vue:108` `const next = (cur + dir + btns.length) % btns.length` → `:109` `btns[next === -1 ? 0 : next].focus()`。`cur` 初值 `indexOf` 可为 -1，但 `-1 + dir + length` 对 `length≥1` 恒 ≥0（dir=1→length，dir=-1→length-2），取模后不可能为 -1，故三元左支永不到达。

**为什么**：不是 bug，是恒假分支；但更实际的后果是「焦点还在列表本身（未选中任何项）时按 ↑」会跳到 `length-2`（倒数第二）而不是末项——`next===-1` 那层本想兜的正是这个「未选」态。

**建议**：把「未选」判定放在取模前（`cur<0` 时 dir>0→0、dir<0→length-1），去掉恒假的 `next===-1`。
