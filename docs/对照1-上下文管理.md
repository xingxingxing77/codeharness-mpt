## 四、缺口与风险（按优先级）

1. **token 兜底「有代码、无绿门禁」= 还不能算数**。本轮把裁剪接进了 `ainvoke` 唯一出口（`gateway.py:179-188`），方向对（一处覆盖经典线 + 动态线两条线，正是收口点）。但 `s13_compress.py` 的 t2/t3 在换口径后**当场复跑 FAIL**，等于「兜底存在」这件事目前没有不花钱的证据背书。而 `LengthFinishReasonError`（输入超窗 vs 输出被截，`gateway.py` 文档头第 2 件事）的归因误导风险，要等门禁转绿才算真收口。
2. **经典线记忆仍不回喂**。`agent.py:128` 那段回喂代码因 `Agent` 无 `self.memory` 而永不执行（§五-8）。第二、三个动作看不到第一个动作的产物全文，只能看 `instruct_content` 透传结构体（`:134`）。当前没暴露，是因为经典线五角色链每角色基本只跑一两个动作、SOP 产物都走 `CONTEXT_WIRING` 显式装配——一旦有角色在同一轮里做多轮修订，这个洞就会现形。
3. **REACT 选择只看一条消息的 2000 字**。`agent.py:107` 硬编码 `s["inbox"][-1].content[:2000]`，无 token 口径。源的 REACT 是把整个 memory 交给模型选数字。
4. **`Agent` 侧零压缩**。`_compress` 只存在于 `role_zero.py:110`；`s["memory"]` 在 `TeamState.memories` 里**只增不减**，长会话的存储（一旦 prompt 接线后还包括 prompt）都会线性膨胀。
5. **压缩配置仍是残缺复制**。`configs/compress_msg_config.py:7-21` 缺源 `__missing__`（未知值退化 NO_COMPRESS）与 `get_type`/`cut_types`；从环境变量传不认识的压缩类型会直接 pydantic 校验失败，源是静默退化。且**这个枚举整体在生产里无人读**（见 §五-2）。
