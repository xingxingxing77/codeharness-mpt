## 设计令牌层（F1）

逐值移植自 `ui-theme/src/styles/{base,design-platform,gradient-shadow-text,scrollbar}.css`，
**令牌名保留 `--dsw-*` 原样**，这样组件 CSS 可以照抄源规则、不必改名。

- 深色是 **presence 属性** `body[data-ds-dark-theme]`，浅色是**该属性不存在**。
  写 `="light"` 永不命中——`hljs.css` 最初就踩了这个。
- 令牌声明在 `body` 上，自定义属性**只向下继承**：任何 `var(--dsw-*)` 的间接层
  必须坐在 `body` 或其后代，放 `:root` 会解析成 guaranteed-invalid
  （桥接表放 `:root` 时侧栏背景直接变透明）。
- 滚动条两条渲染路径互斥且门控承重：`@supports not selector(::-webkit-scrollbar)`
  走标准属性（Firefox），否则走 `::-webkit-scrollbar*`（WebKit）。同时声明会让
  支持 hover 伪元素的引擎反而拿不到 hover 效果。
- **不裁剪色板**：这层是 vendored 的，裁剪要求每条源规则做令牌改名手术，等于丢掉
  「可对照源排错」这个最大优势。改用 `scripts/contrast_report.py` 做体检不做门禁。

对比度实测：深色 13 项全达标；浅色 5 项低于阈值（三级文字 3.71、caption 2.13、
错误红 4.50 压线、成功绿 2.28、警示文字叠警示底 2.58）——**全是参考项目自身取值**，
按一比一口径保持不改。

## 布局几何契约（F2）

逐值照抄 `ui-layout/src/client/columns.ts`：

```

DETAILS 300/520/360
```

让渡链：侧栏永不退让 → details 先缩到 300 再整体关闭 → center 吸收最后缺口。

**起点宽度在 pointerdown 冻结**（抓起被让渡压过的面板不会跳）、松手时把还在排队的
最后一帧就地结算。details 关闭时必须去掉那条 1px 左边框接缝，而收起的侧栏保留
有边框的紧凑轨。视口宽用 rAF 节流的 ResizeObserver 量在**帧元素**上（不是 window）。

## 轮次聚合与尾行（F5 补齐）

`utils/turns.ts:buildRows()` 把块表摊成一维行序列 `{kind:'node'|'tail'}`，中栏按它渲染。

- **断轮依据是用户发言，不是 `role`**：后端两条发射路径写的不是同一个名字——报道槽
  （`codeharness/report.py`）写角色名 `PM/Architect/Engineer…`，打字机流
  （`server/runner.py:_translate`）写 langgraph 节点名 `act/think…`。按 role 断轮会把
  一个角色的一段工作切碎，尾行落到句子中间。所以一轮 = 一条用户发言到下一条之间的全部
  助手输出，对齐参考项目的 `turn`（一次用户请求）+ `step`（轮内多次 LLM 调用）。
- **尾行只在末块 `closed` 后挂**：参考项目在 `turn/end` 才发布 `turn-tail`，否则「用时」
  会在流式期先冒出来逐帧跳。本轮没有收口正文（只有工具调用没说话）则整行不出现。
- **三个读数各自的来源**：时钟取轮末块的 `lastTs`（块级 `ts/fts/lastTs` 由 `applyEvent`
  从事件 `ts` 落，参考项目 `formatMessageClock` 同日 `HH:mm`、同年补 `M月D日`、跨年补年）；
  `用时 = endTs − startTs`；`tok/s = 窗口内 span.ct 之和 ÷ (末块时间 − 首 token 时间)`，
  span 来自 `/trace`。**块与 span 一律 unix 秒，只有读数组件要 ms**，换算在边界做。
- **TTFT 缺位是有意的**：事件流里没有 LLM 派发时刻（打字机流块首个事件就是 `content`，
  内核块 `meta/content` 同毫秒），硬算出来的读数恒为 0 秒。升级路径：`server/runner.py`
  接 `on_chat_model_start`，给 `/trace` 的 span 补 `t0` 与首 token 时刻，尾行 TTFT 与
  StatsLine 的 LLM 耗时一起吃这份数据。
- 几何照抄：`ReasoningRow` 折叠摘要行 = 24px 行、三级文字色、14/24、`Think` 标题 400 字重
  + `IconThinkOutline14`（16 号那份在参考项目里没有生产消费者）、body 左缩进 22px、
  流式期摘要滚到行尾（`text-overflow: clip` 不用省略号）；`MessageIconActions`
  = 行高 28px、图标间距 10px、读数间点距 `margin:0 10px`、hover 淡入 `80ms ease`
  （靠 `data-time-hover-root` 作用域，`opacity` 不改布局，`@media (hover:hover)` 才收起）。

## Trajectory 台账与视图切换（批次14）

会话头下面一条 `Chat | Trajectory` 页签条（照抄 `.tabs`：gap 36px、margin-top 4px、
padding-left 8px；`.tab` 13/16 wt500 三级色、下内边距 11px、`::after` 2px 圆角下划条；
选中态走**业务蓝**——`brand-primary` 在这张令牌表里落成中性黑，业务蓝是两套主题下都保持蓝
的最近语义令牌）。

- **台账一行 = 一次 LLM 调用**（`/trace` 的一个 span）+ 它时间窗内产出的块：
  `utils/trajectory.ts:buildTrajectory()` 按「块首事件 ts ∈ (上次调用结束, 本次结束]」归属。
  合计行与顶栏成本对得上（实测 14 次调用、入 19827 / 出 58940 / ¥0.1750 vs 顶栏 ¥0.176）。
- **它是「用量 + 产出」台账，不是报文检视**：参考项目能展开每条记录的原始请求/响应体，
  我们没把 prompt 与响应原文落盘。升级路径写在 `trajectory.ts` 的天花板注释里。
- **行点击跳回对话流**：`jumpToBlock()` 切视图后等一次 DOM 更新，按
  `[data-chat-anchor-key]` 定位再 `scrollIntoView({block:'center'})`。实测中间行落在
  scrollTop 930 / 可滚 1740 的中段，不是滚到底。
- **视图切换必须 `v-show` 不能 `v-if`**：参考项目把视图放在**常驻滚动容器**里。用 `v-if`
  切走会把整条 transcript 卸载，切回时重跑 markdown 解析与 mermaid 水合并丢滚动位置
  （实测两次切回都把无头页打崩）。注意 `v-else` 不能配在 `v-show` 后面——那是编译错误，
  而 **`vite build` 会把 Vue 模板编译错误打出来却仍然退出 0**，所以构建后必须 grep 一遍
  输出而不只看退出码。

## StatsLine 统计条（批次19）

会话级统计条，落点照抄参考项目：它是 **composer bar 的 footer**（`conversation.composer.dock`
的 `id:'stats'`），渲染在 composer 卡下方、与卡共用同一个宽度约束，所以挂在
`[data-composer-seat]` 里而不是对话流末尾。几何逐值照 `StatsLine.module.css`：块级（不是
flex，否则超长是从中间裁断而不是收在省略号）、`12/20`、三级文字色、居中、
`max-width: var(--dsh-chat-content-width)`、`padding: 4px calc(var(--dsh-composer-side-clearance) + 16px) 0`、
竖线分组（`.sep` 用 `--dsw-alias-separator-primary`、`margin:0 10px`）、
超宽省略号 + hover 500ms 才出全文，且**只有真的被截断才启用 tooltip**。
takeover（问题卡）整条链被替换时它不出现，空态 hero 也不出现——与参考项目同一条件。

四个读数的来源与「宁缺不假」的口径（算术全在 `utils/stats.ts`，25 条断言守着）：

- **轮 / 步**：轮 = 与 `utils/turns.ts` 同一断轮依据切出的段数（只有用户发言没有输出的一段
  不算一轮）；步 = `/trace` 的 span 条数（我们一笔 span 就是一次 LLM 调用）。
- **LLM 耗时** = Σ(`span.ts − span.t0`)，**首 token 平均** = Σ(`ft − t0`) ÷ 双端齐全的调用数
  ——分子分母必须同批，只有一端就计进分母会把平均值算小。
- **tok/s** = Σ`ct` ÷ Σ(`ts − ft`)，只走 span：块事件里没有 provider usage。
- **输入 / 输出 token** 优先取会话账本（`cost`，全量持久数），账本空着才退到 span 累加。
- **工具耗时只认 Terminal**：它是事件词汇表里唯一有「调用→结果」两次事件（cmd 先、output
  若干）的块型。`ponytail:` 天花板——Docs/Editor 是后端整份一次下发，`ts` 与 `lastTs` 只差
  几十毫秒的到达抖动，逐块累加会给出「工具调用 0s」这种没有证据的读数（批次19 首版就是这么
  露馅的）。升级路径：后端给工具也记 span，届时改读 span。
- **缓存命中率 / 上下文占用**不画：我们没有 `cacheReadTokens` 也没有 `contextWindow`，
  按「没数据的分组整段丢掉」处理。

批次19 实测（本机 ollama `qwen2.5-7B` 真跑，会话 `07dde7a9`）：
`1 轮 · 15 步 | LLM 59.8s | 首 token 平均 0.6s · 46 tok/s | 输入 7K tok · 输出 2.4K tok`，
探针回读 `groups=4 / seps=3 / font=12px/20px / color=rgb(129,133,140) / align=center /
width=748 / inSeat=true`，三次连跑数值一致。

## 侧栏 HoverCard 与手动排序（批次21）

**HoverCard**（`components/ui/HoverCard.vue`，逐值照 `ui-primitives/HoverCard.tsx` +
`Rows.module.css`）：500ms 停留才出卡、卡 244 宽挂在 body 上、贴锚点右缘 8px、
`top` 按视口底边钳位、跟随 scroll(capture)/resize 重定位。三条不可省的 mechanics：
① 卡**吃指针事件**（不是 `pointer-events:none`），离开锚点只武装 200ms 宽限关闭，
所以指针能跨过那道缝落在卡上读被截断的标题；② 锚点内按下立即收卡（不等 owner 翻
`disabled`），但按在卡上不收——那是一次选区起始；③ 可复制时点卡即复制、显示 1s
「复制成功」，期间用 `minHeight` 钉住原高度免得卡片抽瘪。菜单开着或拖拽在飞时禁用。
实测（无头 1280×900）：220ms 时无卡、950ms 时有卡、`cardW=244`、`topAligned=true`、
`inBody=true`、宽限期内回到卡上卡不消失。**唯一没验到的**是「复制成功」回执——
无头里 `clipboard.writeText` 没有用户激活直接被拒，这条要在可见面板里点一次才算闭环。

**拖拽排序**：行（`SessionRow`）只报「落在哪一行的上半/下半」（`rowHalf` 同参考项目），
插位由 owner（`WorkspaceBrowser`）算——因为基准必须是当下渲染出来的那串 id，行自己
看不到兄弟节点。落点写进 `workspaceView.manual[组键]`（未分组桶键是空串，平铺模式同），
并自动把 `orderBy` 切成 `manual`；`applyManual` 靠 `Array#sort` 的稳定性让表里没有的
新会话保持时间序整体排在最后。搜索态不给拖（拖的是过滤后的半截列表）。插入标记
`.dropBefore/.dropAfter` 逐值照抄（55 度业务蓝斜线、12px 高、上沿 `top:-7px`、下沿 `bottom:-7px`）。

实测：组 `MetaGPT` 三行 `[7c8bcd93, b1403f12, d9f62638]` 拖第一行到第三行下半 →
`[b1403f12, d9f62638, 7c8bcd93]`，落盘 `{"orderBy":"manual","manual":{"MetaGPT":[...]}}`，
刷新后渲染顺序仍是这张表的样子；marker 在 drop 后清掉；行高 32px 不变、
`indented` 仍在行元素上（HoverCard 包了一层，所以 `inheritAttrs:false` + 手工
`v-bind="$attrs"`）、列表无横向溢出。

**顺带查出一个从 F3 就在的真 bug**：`workspaceView.persist()` 写的是
`JSON.stringify({ ...this })`——展开 pinia option store 会把内部引用一起卷进去，
`TypeError: Converting circular structure to JSON`（`component → vnode` 成环）当场抛出，
于是**分组展开、排序、归档区开合从来没落过盘**（内存里改了所以界面上看着正常，
只在控制台留一条报错）。改成逐键取 `{ groupBy, orderBy, expansion, archivedOpen, manual }`。
这条是「构建绿 + 界面正常」骗住的一个静默失效，`npm run build` 与门禁都不会报。

## Composer 逐值对齐（批次22）

先说结论：**卡体本来就是对的**，实测 `max-width 780 = 内容列 748 + 两侧 16`、`radius 22px`、
`border 1px var(--dsw-alias-border-l2-darkmode-thin)`（浅色 `rgba(0,0,0,.1)`）、
`background var(--dsw-specific-input-major)`、`box-shadow var(--dsw-shadow-lv2)`
= `0 4px 12px rgba(0,0,0,.02), 0 2px 8px rgba(0,0,0,.04)`、textarea `padding 4px 12px 0 16px`
与 `16/24`、placeholder 走 `--dsw-alias-label-caption`。逐值对 `InputBar.module.css` 都在。

这次真正改掉的四处分歧：

1. **模型名是填充灰胶囊**（`bg --dsw-alias-bg-module-platform` + `radius 14` + 12 号字），
   而参考项目的模型/模式控件是 `.select` 质感：**透明底、`radius 8`、`13/20`、wt500、二级字、
   `max-width 220px`**。而且原来连 `max-width` 都没抄，只有 `nowrap`——所以模型名一长
   （本机 ollama 的 `qcwind/qwen2.5-7B-instruct-Q4_K_M` 35 字符）就把整行右半边顶开。

## 流式与滚动（F5）

- **合帧**：SSE 事件先进 `pending` 队列，一帧结算一次。参考项目用 rAF，但 rAF 在
  不可见页里根本不触发，所以同时挂 32ms 定时器谁先到谁结算。换会话时缓冲与已排队
  结算一起清（`applyEvent` 只认游标不认 session）。
- **滚动跟随**：`FOLLOW_THRESHOLD=24`。不注册 wheel/touch，改为每次程序化写入记下
  `observedTop`，用 `|scrollTop − min(observedTop, floor)| > 0.5` 反推「读者动过」；
  浏览器缩窗钳位会精确落在 floor 上因此不误判。跟滚只在「末节点是用户自己的话
  （强制）/ followSig 变化且仍钉住」时发生。
- **增量 markdown**：除末尾 2 个顶层块外全部冻结成缓存，只重解析尾部。块文本含结尾
  换行，所以冻结边界停在换行后，渲染结果与整篇一致。
- **微光三件套**：行扫光 300px 带 `2.6s ease-out infinite`（尾 10% 留一拍）、
  轮次文字 `1.8s linear infinite`、状态点 8 格像素追逐 `1s` 逐格 `delay=(i-8)*125ms`。
  耗时 **15s 之后**才出现。

## SSE 游标与断线（F4）

`seq = ms*10^6 + cnt ≈ 1.79e18` 远超 `2^53`，过 `JSON.parse` 舍入到 ulp=256，
同毫秒内上千事件塌缩成几个不同值 → 前端 `ev.seq <= lastSeq` 吞事件。
实测铁证：`1789814825483000000` → `1789814825483000064`。

修法：`Event.cursor` 定宽补零字符串（Redis 侧 `f"{ms:013d}-{cnt:06d}"`，进程内侧
`f"{n:019d}-0"`），字典序即等于数值序；`after` 参数收串（仍吃裸数字做兼容）；
`seq` 保留 int 供服务端内部精确排序。旧事件缺 `cursor` 时由 validator 从 `seq` 兜底。

顺带修掉 `flush_now()`：它承诺「刷干净」却只等 ring 空，而 `_flush_loop` 一次性把
整批 `popleft` 出来、ring 立刻空但上千次 `xadd` 还在路上 → 按它判定会让**停机路径
丢掉整批事件**。加在途批次计数。

重连三级：L1 交给 EventSource 原生重连 + 带 `after=cursor`；L2 打既有
`/events/history`；L3 持续断线才提示条（**B1 已落地**：`store.stream==='down'` → `App.vue` 的
`.connBanner`，实测杀掉后端 0.8s 内现身、重连 `onopen` 自清，且 `after=<游标>` 续推不把已渲染块重播一遍）。
**不做**自造退避包装器（那要求弃用
EventSource 改 fetch-stream 自己解析帧），**不做** 500 容量 Set 去重（单调游标
O(1) 且天然正确，Set 在回放超 500 条时会重复渲染）。

## takeover 优先级栈（F6）

composer 座位是**一个槽位、多个竞争者**：问题卡 > 审批条 > 常规 composer。
写成优先级数组而不是模板里的 `v-else-if`——将来加审批条是往数组前面添一项。
共用同一个 sticky 座位，所以切换是替换不是布局跳动（实测对话节点数不变）。

后端目前只有 `ask_human` 一种挂起交互，且 `Event.value` 是一条纯文本问题，
所以只做自由文本回答，**不画**选项芯片、分页器、多选框。

## 「不做」的三档口径（2026-09-19 修订）

原稿这一节是一句「后端没有所以不做」的清单，里面混进了**其实纯前端就能做**的条目，

**档一 · 真不做**——本平台没有那个子系统，画出来只能是真的假壳子：

## 回滚口径

不做 feature flag 与 `legacy/` 双布局并存：前端由同一个 FastAPI 进程
`StaticFiles(html=True)` 挂 `frontend/dist`，只有一份产物、单机、无按用户分流，
也不存在「线上错误率基线」这个可观测量；而双布局要求每个新组件在两套令牌下各跑一遍，
等于把刚删掉的米色令牌全留着。

改用**阶段提交制**：一个 F 阶段 = 一个 commit，回滚单位就是阶段（`git revert`），
需要留档对比时打 `git tag fe-F7-baseline`。

`shot.mjs` 存在的原因：内置浏览器面板不可见时页面 `innerWidth` 为 0、rAF 不跑，
截图被挡、帧宽 ResizeObserver 也拿不到新宽度。系统里本来就有 Chrome/Edge，
Node 22 自带全局 `WebSocket`，所以直接讲 CDP，零新依赖。关键是
`Emulation.setDeviceMetricsOverride` 显式钉住 CSS 视口——无头的 `--window-size`
不等于 CSS 视口。

**探针的 `-32000 Execution context was destroyed` 不是页面崩了**（批次19 查清，
订正批次14/16 记下的「无头抖动、重跑即可」）：`--eval` 是 `awaitPromise` 的长求值，
而 `shot.mjs` 过去一连上 page target 就发出去。Chrome 在导航提交前就把 target 的
`url` 报成本次 URL，那一刻文档其实还是 `about:blank`——它的 `readyState` 本来就是
`complete`，所以「等 readyState」不构成屏障；真正文档提交时上下文被销毁，长求值当场死掉。
判据必须是两条一起用：页面自己的 `location.href === 本次 URL` **且** `readyState==='complete'`，
再加 300ms 让 Vue 挂载完。附带把写死的调试端口 9333 换成每次随机（旧实例没退净时
`/json/list` 会返回**上一个浏览器**的 target），并且只认 URL 完全一致的 target。
同一段探针求值：修之前 3 次里崩 2 次，修之后 5/5 稳定返回。
