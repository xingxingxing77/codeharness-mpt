> 界面 1:1 复刻 `E:\deepseek-harness`（React 18 + CSS Modules + cordis 插件/slot 框架），
> 数据全部对接**本项目自己的后端**（20 条路由 + 5 类 SSE 事件）。

## 设计令牌层（F1）

逐值移植自 `ui-theme/src/styles/{base,design-platform,gradient-shadow-text,scrollbar}.css`，
**令牌名保留 `--dsw-*` 原样**，这样组件 CSS 可以照抄源规则、不必改名。

- 深色是 **presence 属性** `body[data-ds-dark-theme]`，浅色是**该属性不存在**。
  写 `="light"` 永不命中——`hljs.css` 最初就踩了这个。
- 令牌声明在 `body` 上，自定义属性**只向下继承**：任何 `var(--dsw-*)` 的间接层
  必须坐在 `body` 或其后代，放 `:root` 会解析成 guaranteed-invalid
  （桥接表放 `:root` 时侧栏背景直接变透明）。
- 滚动条两条渲染路径互斥且门控承重：`@supports not selector(::-webkit-scrollbar)`
  走标准属性（Firefox），否则走 `::-webkit-scrollbar*`（WebKit）。同时声明会让
  支持 hover 伪元素的引擎反而拿不到 hover 效果。
- **不裁剪色板**：这层是 vendored 的，裁剪要求每条源规则做令牌改名手术，等于丢掉
  「可对照源排错」这个最大优势。改用 `scripts/contrast_report.py` 做体检不做门禁。

对比度实测：深色 13 项全达标；浅色 5 项低于阈值（三级文字 3.71、caption 2.13、
错误红 4.50 压线、成功绿 2.28、警示文字叠警示底 2.58）——**全是参考项目自身取值**，
按一比一口径保持不改。

## 布局几何契约（F2）

逐值照抄 `ui-layout/src/client/columns.ts`：

```
CENTER_MIN 640  SIDEBAR 264/420/280/收起 56  AUTO_COLLAPSE 1024（严格小于）
DETAILS 300/520/360
```

让渡链：侧栏永不退让 → details 先缩到 300 再整体关闭 → center 吸收最后缺口。
纯函数、无断点、无滞回，所以视口重新变宽时偏好自动恢复（偏好从不被改写）。
求解器输入必须是**有效收起态投影出的偏好**（收起时喂 0，由求解器映射成 56px 轨），
直接喂 `panels.sidebar` 会让窄视口自动收起只翻属性、轨道仍停在 280px。

拖拽：8px 条骑在边界（`margin-left:-4px`）、pointer capture + 单 rAF 节流、
**起点宽度在 pointerdown 冻结**（抓起被让渡压过的面板不会跳）、松手时把还在排队的
最后一帧就地结算。details 关闭时必须去掉那条 1px 左边框接缝，而收起的侧栏保留
有边框的紧凑轨。视口宽用 rAF 节流的 ResizeObserver 量在**帧元素**上（不是 window）。

## 流式与滚动（F5）

- **合帧**：SSE 事件先进 `pending` 队列，一帧结算一次。参考项目用 rAF，但 rAF 在
  不可见页里根本不触发，所以同时挂 32ms 定时器谁先到谁结算。换会话时缓冲与已排队
  结算一起清（`applyEvent` 只认游标不认 session）。
- **滚动跟随**：`FOLLOW_THRESHOLD=24`。不注册 wheel/touch，改为每次程序化写入记下
  `observedTop`，用 `|scrollTop − min(observedTop, floor)| > 0.5` 反推「读者动过」；
  浏览器缩窗钳位会精确落在 floor 上因此不误判。跟滚只在「末节点是用户自己的话
  （强制）/ followSig 变化且仍钉住」时发生。
- **增量 markdown**：除末尾 2 个顶层块外全部冻结成缓存，只重解析尾部。块文本含结尾
  换行，所以冻结边界停在换行后，渲染结果与整篇一致。
- **微光三件套**：行扫光 300px 带 `2.6s ease-out infinite`（尾 10% 留一拍）、
  轮次文字 `1.8s linear infinite`、状态点 8 格像素追逐 `1s` 逐格 `delay=(i-8)*125ms`。
  耗时 **15s 之后**才出现。

## SSE 游标与断线（F4）

`seq = ms*10^6 + cnt ≈ 1.79e18` 远超 `2^53`，过 `JSON.parse` 舍入到 ulp=256，
同毫秒内上千事件塌缩成几个不同值 → 前端 `ev.seq <= lastSeq` 吞事件。
实测铁证：`1789814825483000000` → `1789814825483000064`。

修法：`Event.cursor` 定宽补零字符串（Redis 侧 `f"{ms:013d}-{cnt:06d}"`，进程内侧
`f"{n:019d}-0"`），字典序即等于数值序；`after` 参数收串（仍吃裸数字做兼容）；
`seq` 保留 int 供服务端内部精确排序。旧事件缺 `cursor` 时由 validator 从 `seq` 兜底。

顺带修掉 `flush_now()`：它承诺「刷干净」却只等 ring 空，而 `_flush_loop` 一次性把
整批 `popleft` 出来、ring 立刻空但上千次 `xadd` 还在路上 → 按它判定会让**停机路径
丢掉整批事件**。加在途批次计数。

重连三级：L1 交给 EventSource 原生重连 + 带 `after=cursor`；L2 打既有
`/events/history`；L3 持续断线才提示条。**不做**自造退避包装器（那要求弃用
EventSource 改 fetch-stream 自己解析帧），**不做** 500 容量 Set 去重（单调游标
O(1) 且天然正确，Set 在回放超 500 条时会重复渲染）。

## takeover 优先级栈（F6）

composer 座位是**一个槽位、多个竞争者**：问题卡 > 审批条 > 常规 composer。
写成优先级数组而不是模板里的 `v-else-if`——将来加审批条是往数组前面添一项。
共用同一个 sticky 座位，所以切换是替换不是布局跳动（实测对话节点数不变）。

后端目前只有 `ask_human` 一种挂起交互，且 `Event.value` 是一条纯文本问题，
所以只做自由文本回答，**不画**选项芯片、分页器、多选框。

## 明确不做的东西

后端没有对应能力，一律不画假壳子：附件上传（`ChatReq` 纯文本）、审批策略与权限预设、
子代理树、后台 job 列表、消息编辑/重生成、单步取消、模型目录（`llm_override` 存了但
`_make_llm` 从不读，接进去之前模型选择器只能是只读展示）、工作区实体
（所以项目行没有 ⋯ 菜单，只有「+ 新建会话」）、内容检索（搜索只匹配标题）。

也不引入新前端依赖：tailwind / shiki / vue-i18n / vue-router / stylelint / axe-core
全部不装。参考项目的 shiki + 增量 parser 用现有 `markdown-it` + `highlight.js` 近似，
冻结边界策略照抄。

## 回滚口径

不做 feature flag 与 `legacy/` 双布局并存：前端由同一个 FastAPI 进程
`StaticFiles(html=True)` 挂 `frontend/dist`，只有一份产物、单机、无按用户分流，
也不存在「线上错误率基线」这个可观测量；而双布局要求每个新组件在两套令牌下各跑一遍，
等于把刚删掉的米色令牌全留着。

改用**阶段提交制**：一个 F 阶段 = 一个 commit，回滚单位就是阶段（`git revert`），
需要留档对比时打 `git tag fe-F7-baseline`。

`shot.mjs` 存在的原因：内置浏览器面板不可见时页面 `innerWidth` 为 0、rAF 不跑，
截图被挡、帧宽 ResizeObserver 也拿不到新宽度。系统里本来就有 Chrome/Edge，
Node 22 自带全局 `WebSocket`，所以直接讲 CDP，零新依赖。关键是
`Emulation.setDeviceMetricsOverride` 显式钉住 CSS 视口——无头的 `--window-size`
不等于 CSS 视口。
