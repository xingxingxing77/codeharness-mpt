## 零、不做清单（2026-09-14 定案，先于一切判定读）

**源项目的「预算管理」不移植。** 精确边界是**砍预算强制、保留计量**：

| 处理 | 内容 |
|---|---|
| **不做** | 预算上限判断与拦截（`max_budget`/`total_budget`/`check_budget`/`is_within_budget`/`update_budget`）、`NoMoneyException`、图上的 `budget_guard` 节点、`TeamState.budget_used`、建会话时的「预算（美元，超限自动停止）」输入、前端的「$已用 / $预算」与「每月使用限制」进度条 |
| **保留** | token 计数（上下文压缩按 `DEFAULT_MAX_TOKENS` 触发，**删不得**）、每轮 token/成本累计、trace 里的耗时与 token 归因。成本数字**只读**：展示、观测、事后统计，绝不作为"这一问值不值得发"的判据 |
| **拆出去** | N5 原本把两件事捆在一起——**分布式限流保留**（多 worker 平台必须有，归到 N1 的配额项），**每用户每会话预算作废**。N5 条目按此拆分，不再是一个整体 |

**为什么砍**：预算/配额属于计费域。多用户平台真要做限额，将来落在网关或计费外壳（按 user_id 计数、超限时在 HTTP 入口拒绝），不该进 agent 编排内核——内核一旦被 `max_budget` 污染，`team_graph` 就凭空多一个没有信息量的节点。

**现存代码里这条线从未生效，所以删除零功能损失**（2026-09-14 实测）：
- `environment/team_graph.py:126` 的 `budget_guard` 比的是 `state["budget_used"] >= settings.max_budget`，而 `budget_used` 全仓库**只有初始化写 0.0、没有任何累加写入**，条件恒假；这个节点既不调 `CostManager` 也不抛 `NoMoneyException`，纯粹是个空转的图节点。
- `provider/cost.py` 的 `check_budget` / `is_within_budget` 在生产路径**零调用方**，只有 `tests/s2_gateway.py` 在自证。
- `server/runner.py:151` 把 `c.total_budget` 当 `max_budget` 发给前端，而 `total_budget` 只有 `update_budget()` 会动（无人调用），恒为 0 → 前端 4 处预算展示从来没显示过预算。
- S3 施工文档从未要求过 `budget_guard`——它是绕过判定表长出来的。

|---|---|---|
| `复` | 纯资产/纯函数,与新栈无冲突 | cp 过去,只改 import 前缀 |

### ⚠ 判 `重` 的纪律（此处已踩过一次）

**一个源文件若同时承担两件正交的事，必须拆开判，不能整体判 `重`。**

实例：`base_serialization.py` 原与 `utils/serialize.py` 合并判为 R4「→ checkpointer」。但两者管的是不同的事——

| 关注点 | 谁负责 | 新栈是否替代 |
|---|---|---|
| **存到哪儿**（写 JSON 文件 / 断点续跑） | `utils/serialize.py` | ✅ checkpointer 取代 |
| **还原成哪个类**（多态类型标签 `__module_class_name` + 子类注册表 + `extra="forbid"`） | `base/base_serialization.py` | ❌ **checkpointer 同样需要**；LangGraph 存 pydantic 也有"字段声明基类、值实为子类"的丢字段问题 |

合并判定的后果：S1 实操时 `SerializationMixin` 直接继承了 `BaseModel`，多态能力静默消失。恢复它之后，`extra="forbid"` **立刻**抓出 `team_graph` 往 `CodingContext` 里塞了一个源模型不存在的 `instruction` 键（此前一直被 pydantic 默认策略静默丢弃）。

**同类要警惕的还有**：R2 的 `action_node.py` 里"字段级定向重试"与"整结构解析"是两件事；R8 的 `tool_registry.py` 里"注册表数据结构"与"函数签名反射"是两件事。**判之前先问：这个文件承担了几件事，哪几件被替代了。**

## 动手前必须先定的两件事

1. **R2(ActionNode 字段级能力)**:`with_structured_output` 是整结构级,源是字段级。要么接受一次成功率/成本退步,要么把 R2 做成通用 validator 中间件。**我建议后者,并且它是 N3 的前置。**
