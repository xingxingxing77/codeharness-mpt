### 必须自己写清楚的四处
1. **`Message` 的 6 个 validator**：`check_id` / `check_instruct_content`(要能接 dict **和** pydantic 模型两条路径)/ `check_cause_by` / `check_sent_from` / `check_send_to` + `field_serializer` 的 `set↔list`。
   ⚠ `cause_by` 的语义:**为空才落 `USER_REQUIREMENT`,已显式给出时绝不覆盖**。源在这里有无条件覆盖的问题,它会让 watch 订阅整体失效——你已踩过。
2. **`instruct_content` + `instruct_schema` 两态**：新栈用「dict + 模式名」替代源"动态造类"。序列化后必须能原样还原。
3. **`RequirementTag` 的值必须等于源 Action 类名逐字**：源拿 43 个 Action 类名当 tag,你用字符串常量替代(`改`,正当),但 `"WritePRD"` vs 源类 `WriteTasks` 这类不一致现在就要逐个对齐,否则后面 watch 对不上是静默失败。
4. **路由短名归一 `_tag` / `_tag_set`**（S1 实操补上的第四处）：`utils/common.any_to_str` 里的 `get_class_name`(common.py:390) 返回 `module.Class` **全限定名**，而新栈 tag 全是短名 —— 混用不报错、只会让 watch 静默失配。`Message` 的 `cause_by`/`sent_from`/`send_to` 一律走 `_tag`/`_tag_set`；⚠ 并且 `_tag_set` 必须像源 `any_to_str_set`(common.py:405) 那样把**标量归一成单元素集合**，直接对 str 做集合推导会把 `"self"` 拆成 `{'s','e','l','f'}`。

### 门禁 `tests/s2_gateway.py`
- 不联网:同一批消息构造的 `payload` 与录制快照逐字段相等
- FakeLLM 跑一次 `aask` → token 与 cost **三字段非零**
