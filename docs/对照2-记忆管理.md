## 四、缺口与风险

见 §结论速览 的四条（经验池租户**本轮补但空转** / kb 切片**本轮补但没通电** / reranker 默认先炸 / 无数据生命周期出口）。补充两条：

5. **门禁可以在零外部服务的情况下全绿**。`s5_memory_rag.py` 的 `t12/t13/t15–t18/t23/t25` 全部经 `live_qdrant()` / `live_embedding()` / `live_redis()` 短路（`:260,743,39`），离线时打印「跳过」并 return，而 `main()` 末行仍打印「S5 门禁通过：{len(checks)} 组」——`checks` 是硬编码的 30 元素清单（`:945-963`），**计数不随跳过减少**。开头有三行 ⚠ 提示，但脚本退出码不区分。R9 这层（也就是本子系统最要紧的升级点）必须起容器跑一次才算数。
6. **`_filters` 的空值即放宽**（`qdrant_store.py:109` `if v`）：调用方漏传 `project` 会静默从「项目切片」放宽到「整个 user 切片」。这是便利，也是漏 filters 时不报错的成因。本轮 `UploadKB`/`aembed_documents` 默认 `user_id` 走的是参数默认，没经 `_filters` 收紧，一旦真接线要连带 §四-6 一起想清楚。

BrainMemory 的 knowledge 轨整条空转**：`:27 knowledge` + `:60-61 get_knowledge()` 都在，但 `add_knowledge` / `.knowledge.append` / `get_knowledge` 在 `codeharness/`+`server/` 命中 0（源侧唯一读者是 `assistant.py:101`）。同理 `add_talk:38`、`add_answer:44`、`exists:56`、`pop_last_talk:57`、`history_text:68`、`is_history_available:64` 六法生产零调用（只有 `t3` 打过 add_talk/add_answer）——`role_zero.py` 走的是 `add_history:125` 单点。
