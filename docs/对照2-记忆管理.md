# 对照 2 · 记忆管理 · 本项目 vs 源 MetaGPT

> 口径与状态词汇见 `对照1-上下文管理.md` 文件头。源快照 `E:\MetaGPT\metagpt`（version=1.0.0），本项目 `E:\Codeharness`。
> 判定账本：`docs/判定-复制与重构清单.md`。本文件只记**现状核对**：源有 → 本项目在哪 → 是否在跑。

## 结论速览

**实现度：约 70%，是六个子系统里覆盖最全的一片，但「覆盖」集中在被替换掉的底座上，源侧一半的记忆能力本身已废弃。** 记忆分三条线，本项目对这三条线的处理各不相同：

| 线 | 源状态 | 本项目状态 |
|---|---|---|
| 短期/工作记忆（`Memory` + `MessageQueue`） | 在用 | 已复刻（但索引面 8/13 方法零读者） |
| 经典线长期记忆（FAISS `LongTermMemory`） | **源自己已注释废弃**（`roles/role.py:104` 字段注释、`memory/__init__.py:12` import 注释） | 有意不做（判据成立） |
| RoleZero 线长期记忆（Chroma） | 在用，默认开关 `enable_longterm_memory=False` | 现代化替换为 Qdrant hybrid + rerank |
| 经验池 `exp_pool` | 在用，默认全关 | 现代化替换（Qdrant + Redis 命中计数） |
| RAG 框架层（`rag/` ~1,400 行） | 在用 | 有意不做（台账 #11 已删件） |

四条最要紧的缺口：

1. **经验池没有账号边界**（已核实，非推测）：`CURRENT_USER` 在全仓只有 `memory/longterm.py:61-62` 一个读者；经验池这条线 `exp_pool/manager.py:41-47` → `document_store/exp_store.py:20-23` 的 `user_id` 恒为构造参数默认值 `"default"`，`get_exp_manager()` 单例也不传。后果：auth 打开后，用户 A 攒下的经验在用户 B 的会话里照样命中并直接返回（`decorator.py:62-65` 命中即 `return`，跳过 LLM）。**N1 的租户切片在记忆面成立、在经验面漏了。**
2. **`doc_type="kb"` 有 schema 无生产者**：`qdrant_store.py:56` 声明 `kb|exp|memory` 三切片、`:91` 还给它建了 keyword 索引，但全仓 `doc_type=` 只出现 `"exp"` 与 `"memory"` 两种（`exp_store.py:29,37`、`longterm.py:89,127,138`）。知识库检索这条能力线**永远召回空**——删 `rag/knowledge.py` 时把上半截删掉了，下半截没人接。
3. **reranker 默认值就是「永远先失败一次」**：`configs/settings.py:25-29` 的 `base_url` 缺省指向 `http://localhost:9998/v1`，`.env` 与 `docker-compose.yml` 都没有 reranker 服务，而 `_rerank`（`longterm.py:101`）的判据只是「URL 非空」→ 每次 `recall` 都真发一次 HTTP 再 warning 降级。
4. **租户数据无出口**：`LongTermMemory.drop`（`longterm.py:137-138`）生产零调用方；`server/runner.py:258-275 _forget` 只清 chat/cost/graph/terminal/editor，删会话既不清 Qdrant 点也不清 `exp_hits:*`。注销/清理义务无处履行。

## 四、缺口与风险

见 §结论速览 的四条（经验池无租户边界 / kb 切片空转 / reranker 默认先炸 / 无数据生命周期出口）。补充两条：

5. **门禁可以在零外部服务的情况下全绿**。`s5_memory_rag.py` 的 `t12/t13/t15–t18/t23/t25` 全部经 `live_qdrant()` / `live_embedding()` / `live_redis()` 短路（`:260,743,39`），离线时打印「跳过」并 return，而 `main()` 末行仍打印「S5 门禁通过：{len(checks)} 组」——`checks` 是硬编码的 30 元素清单（`:945-963`），**计数不随跳过减少**。开头有三行 ⚠ 提示，但脚本退出码不区分。R9 这层（也就是本子系统最要紧的升级点）必须起容器跑一次才算数。
6. **`_filters` 的空值即放宽**（`qdrant_store.py:109` `if v`）：调用方漏传 `project` 会静默从「项目切片」放宽到「整个 user 切片」。这是便利，也是漏 filters 时不报错的成因。

## 五、「看着像有、其实没接线」

- **A. `Memory` 复制件的 8 个方法零运行时读者**：除 `try_remember`（`role_zero.py:105`）外，`get_by_role:46`、`get_by_content:50`、`delete_newest:54`、`delete:64`、`clear:72`、`find_news:89`、`get_by_action:99`、`get_by_actions:104`、`get_by_position:114` 在 `codeharness/`+`server/` 全无调用点（实测 grep 计数为 0），`add_batch:42` 只被自己的 `add` 绕进。`Memory` 的唯一 importer 也只有 `role_zero.py:24`。**`index`（`:29`）因此是只写不读的字典**——源那套「按角色/按动作/按位置取记忆」的能力实际没有兑现，兑现的只有截窗与去重。
- **B. BrainMemory 的 knowledge 轨整条空转**：`:27 knowledge` + `:60-61 get_knowledge()` 都在，但 `add_knowledge` / `.knowledge.append` / `get_knowledge` 在 `codeharness/`+`server/` 命中 0（源侧唯一读者是 `assistant.py:101`）。同理 `add_talk:38`、`add_answer:44`、`exists:56`、`pop_last_talk:57`、`history_text:68`、`is_history_available:64` 六法生产零调用（只有 `t3` 打过 add_talk/add_answer）——`role_zero.py` 走的是 `add_history:125` 单点。
- **C. `SimpleScorer` 不在任何生产闭环上**：`exp_pool/scorers.py:61-72` 完整可用，生产命中 0，唯一读者是 `tests/manual_judge_quality.py:68-71`（真钱通道，自述不进门禁）。相应地 `exp_pool/schema.py:40 Score`、`:47-52 Metric` 除定义外零写入者，`Experience.metric` 恒 None——经验池「带质量分」这半截是空的。
- **D. 三个配置字段是死旋钮**：`settings.py:28-29 reranker.top_n / recall_k` 零读者（`_rerank` 用形参 `k`，HTTP body 里的 `top_n` 传的是 `len(texts)`，`:106-108`）；`qdrant_store.Point.session_id` 从不参与过滤；`ExpStore.save:25 score` 形参被 `manager.create_exp:50` 省略，于是 payload 里的 `"score": h.score`（`exp_store.py:40`）永远是向量分数而非经验分数。
- **E. 稀疏向量是 crc32 词袋**：`qdrant_store.py:34-46` 自注（ponytail）无 idf 语料统计。服务端 `Modifier.IDF`（`:89`）是 qdrant 侧的打分修正，不等于真实语料 idf。所以 hit-rate 对照表只能当方向性证据——`docs/施工2-能力层-S4-S5.md:132` 也是这么写的，别拿它当结论。
- **F. `langchain-qdrant` 在 `pyproject.toml:8` 声明但全仓零 import**——依赖是虚的。

## 六、门禁覆盖（`tests/s5_memory_rag.py` 为主）

**真覆盖**：Redis 往返与死端口降级 t1/t2（`:70-96`）；BrainMemory dirty 才写盘、摘要滚入、分窗收敛 t3–t6（`:99-166`）；工作记忆回喂 / 截窗 / 摘要可恢复 / key 按会话+角色隔离 / 去重容错 t7–t11（`:181-254`）；集合形态四形态 t12（`:306-323`）；`user_id`×`doc_type` 双向隔离 t13（`:326-345`）；sparse 下标跨进程稳定 t14；入库幂等 + 召回字段 + drop t15；召回真进 prompt t16（`:387-404`）；embedding 下线降级 + 熔断零重连 t17/t17b（`:407-444`）；单向量 vs hybrid 的 hit-rate@5 对照表 t18（`:462-523`）；Experience/Serializer roundtrip t19/t20；命中计数改排序 t21；`@exp_cache` 六态矩阵 t22（`:605-667`）；真 Qdrant+Redis 回放 t23；RoleZero 命中零模型调用 t24；真 bge-m3 语义路径 t25；精排接缝离线降级留痕 t28（`:888-907`）；Scorer 模板逐字 + FakeLLM 打分 t29/t30。

**零断言**：
- **生产装配面的 ltm**——所有测试都手工 `role.ltm = …`（`:398,416,439`），没有一条验 `team.default_team:16-20` 造出的实例能否召回；
- **跨会话召回**——无「两条会话共享同一 project」的用例，这是 ltm 存在的全部理由；
- **经验池的租户隔离**——`t13` 测的是 memory 切片，经验切片恒 `user_id="default"`（§四-1）无人测；
- **`doc_type="kb"` 全路径**、`ArtifactStore` ↔ 向量库联动、BrainMemory knowledge 轨、`Point.session_id`；
- 其余五个门禁（`s3b/s7/s8/s9/s10`）除 `s9_benchmark.py:122-126` 借 `QdrantStore` 做纯文本检索外，对记忆子系统零引用。

## 七、建议的收口顺序

1. **给经验池接上 `CURRENT_USER`**（一处）：`exp_store.py:20-23` 的 `user_id` 改成与 `longterm.py:55-62` 同款 property，或 `get_exp_manager()` 按用户建实例。这是当前唯一「越权可见」级别的问题，优先于其它所有条。
2. **`doc_type="kb"` 二选一**：接一个文档摄取入口（`ArtifactStore` → 切片 → `aembed_documents`），或把它从 `qdrant_store.py:56` 的注释与索引里删掉。留着会让下一个人以为知识库已经在了。
3. reranker 缺省改空串（`settings.py:27`），配了才发；把 `top_n/recall_k` 接进 `_rerank` 或删字段。
4. 让门禁诚实：`main()` 统计「实跑组数 / 跳过组数」，有跳过时打印 `SKIP n` 并（可选）非零退出——`docs/README.md` 的门禁基线口径同步改。
5. 补两条用例：跨会话召回、经验池租户隔离。
