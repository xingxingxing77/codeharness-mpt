## 段 3 · 根因

**账面把「资产里有错文本」等同于「运行期隐患」，中间那一环（有没有消费者把这段发给模型）从来没查。**
补上那一环后链条断在源头：三件资产是施工3 批1 按源目录结构整体搬来的**逐字保护资产**，
`WriteAnalysisCode` 这条线在 S4/S6 落地时用的是新栈自写的短 prompt，donor prompt 从没接上
（`对照5 §A 死资产清单`早登记过同一现象，只是没接到 C9 这条账上）。
所以「模型照 prompt 生成 `from metagpt.tools.libs.terminal import Terminal` → 必 ModuleNotFoundError」
这个后果**今天没有触发路径**。

## 段 4 · 解决方案（三项决定，都写理由）

1. **C9 改判 ⛔（不是代码问题）**：既不能改逐字（s6 t1 逐字 + 键集双重锁，第 4 步实测），
   也没有消费处可拼接（第 5 步实测）→ 在 `actions/data_analysis.py` 里写一个校准常量 = **给一段根本不发给
   模型的文本新增死代码**。账面要求「停止当 bug 追」的另一支同理：把它当 bug 追会产出错的东西。
   **重开条件**写成硬话并落在 `对照3` §结论-2 末段：**谁把这三件资产接进生产，谁同批在消费处加法拼接校准常量覆盖那句 metagpt 指引**（那时才有落点，`PRD_STACK_CALIBRATION` 先例那时才成立）。
2. **回写账面**（`对照3` 四处 + `PLAN` 一行）：`:6` 复核段 ③、`:15` §结论-2（整条改判 + 实测证据 + 重开条件）、
   `:100` `data_preprocess.py` 行（引用它的那段 prompt 也在零消费者资产里，两头都是死件）、
   `:117` §五「t38 管不到」补「成立但不是盲区」、`:122` §六-2 **作废**（三条理由，含「这道 grep 与 s6 互斥」）。
   这一步的必要性：`:15` 与 `:122` 的旧处方**留着比删掉更危险**——下一棒照着做就是写死代码或把 s4 打红。
3. **`tests/s4_tools.py:550-552` t38 docstring 同批改口径**（唯一一处非文档改动，纯注释、无行为变化）：
   原文「正解=加法拼接校准常量、不动逐字」是本轮实测否掉的那句话，且漏列 `metagpt_sample.py`。
   跑法照 §0.4 三条姿势 → 读数见段 5。
4. **明确否掉「加一道零消费者门禁」**（记下来免得下一棒重议）：可以钉「生产码不得引用这些常量」，
   但它会在**正确**的未来（DI 线真要装配 donor prompt + 校准）时红，属于跟路线图对着干的反向门禁；
   而今天这件事 5 秒一条 grep 就能复验。按 ponytail 不为假想需求建机制。
