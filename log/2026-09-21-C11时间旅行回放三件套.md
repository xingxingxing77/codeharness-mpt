# 2026-09-21 19:2x · C11：时间旅行回放三件套落地（采集原来是免费的）

用户 18:15 拍板「做，三件套全上」（`plan/PLAN.md` §9 第 3 条），18:5x 起做。
账面原来写的是「机制就位、这件活没做」+「按 superstep 采快照」——**采快照这一件被实测否掉了：
不需要写任何采集代码**，`AsyncSqliteSaver` 每个 superstep 本来就在落一份 checkpoint。

## 段 1 · 现象 / 缺的是什么

checkpointer 在位（`environment/checkpoint.py:82`）、真落断点的用例在跑（`s3b` t7/t8），
但**回放面零**：全仓 `get_state_history` 零命中、没有任何读取端点、界面只有事件 Timeline
（`stores/sessions.ts`），没有超步轴。也就是说"这场会话第 17 步时黑板上是什么"这个问题答不了。

## 段 2 · 排查过程（先取证再设计，载体 `log/c11_probe.py` → 读数 `log/c11_probe.out`）

1. **A 语义层**：两节点小图 + 真文件 saver 跑 4 场 `ainvoke` → `aget_state_history` 回 **12 份**
   （每场 3 份：`source=input` 起点、`source=loop` 待跑、`source=loop` 落账），
   `metadata.step` 单调、`next` 给出下一步是谁、`checkpoint_id` 全不重复且**新→旧**；
   **换一个 compiled graph 实例读同一 thread 仍是 12 份** → 端点可以走 `_ensure_graph` 那条重建路，
   不必持有创建它的那个对象。
   `metadata` 字段实测只有 `['parents','source','step']`（**没有** 我以为会有的 `writes` 明细——
   所以 `writes` 那格在某些 saver 版本/路径下是空数组，界面拿 `tasks` 兜底显示）。
2. **B 真数据层**：直接只读打开仓库里的 `workspace/storage/checkpoints.db`
   （`sqlite3 file:...?mode=ro`，绝不写）→ 35 个 thread、**3513 份 checkpoint、32.4 MB**；
   最单条 `s7e2e` 有 **711 份**、单份最大 **62 KB**；`gate2_classic` 613 份 / 6.9 MB。
   → 结论直接决定形状：**列表绝不回全量 state**，必须摘要 + 点开取单份 + 分页。
3. **API 签名不靠记忆**：`inspect.signature(Pregel.aget_state_history)` →
   `(config, *, filter, before, limit)`，其中 `before` 是 `RunnableConfig`。
   → **`before` 走关键字才是开区间**；把 `checkpoint_id` 塞进 config 是「含它自己」的闭区间语义。
   我第一版就是塞进 config 写的，被这条签名拦下来（B2 那轮踩过同族形状，见
   `log/2026-09-21-B2反向分页与首屏窗口.md`）。
4. **延迟会不会撞上 F2 那条 15s deadline**：在 711 份那条 thread 上实测
   `limit=3 → 0.068s`、`limit=80 → 0.14s`、`limit=200 → 0.31s`；
   第一次请求 7.4s 是**一次性的建图 + checkpointer 预热**，不是每页成本 → 不会被掐。

## 段 3 · 根因（设计层面）

不是 bug，是缺面。设计上要解决的是「langgraph 的历史是 per-superstep 且带全量黑板」与
「浏览器要一屏能看完」之间的矛盾，所以接缝放在**摘要/详情分离**上：
列表 = `CheckpointHead`（7 个字段，无 state），详情 = 单份 state + 体积上限 413。

## 段 4 · 解决方案

1. `server/runner.py`：新增 `_ckpt_page(graph, config, limit, before=None)` —— 多取一条探
   `has_more`、`writes` 只留键名、**页内不携带 values**（`aget_state_history` 会反序列化出来，
   但只在这一格内存活着，出页即丢）。
2. `server/api/sessions.py`：`_cfg_at()` 只做一件事（把 `checkpoint_id` 打进 configurable，
   详情端点用它选快照）；两条路由
   `GET /{sid}/checkpoints?before=&limit=`（默认 80，`ge=1 le=500` 值域 422）与
   `GET /{sid}/checkpoints/{checkpoint_id}`；`MAX_STATE_BYTES = 4 MiB` 超限 413（detail 说清是上限，
   前端已按 `status` 分流）；图重建不出来时列表回 `[] + reason`（不装成"没有历史"）、详情 409。
   归属仍走 `_owned`（auth 开时越权 404）。
3. 前端：`api/client.ts` 两个方法（**参数名刻意用 `checkpoint_id`**，因为 s8 t3 是按
   「模板段名 ≡ FastAPI 占位符名」比形状的，用 `cid` 会被判成"前端消费了后端没有的路由"）；
   右栏新增 **回放** 页签（第 7 个，`ui.rightView` 联合类型加 `'replay'`）：
   超步表（步/来源/下一步/产出/时刻）+ 点行展开该步 state + `加载更早` 胶囊 +
   换会话清游标的 `watch`（不清会把 A 场的超步显示在 B 场名下）。样式全取本文件已有 token。
4. 门禁两条：
   - 新增 `tests/s21_checkpoint_replay.py`（3 组）：t1 单位层（12 份新→旧、字段集钉死、
     页项无 values、**翻页开区间**两页零重叠且边界条不重复、到底 `has_more=false`）；
     t2 端点层（两路由码与形状、**413 正向 + 恢复对照**、`limit` 值域 422、重建失败带 reason/409）；
     t3 只读性（连读 3 轮 + `aget_state` 之后条数不变——端点路径里不许藏写）。
     `main()` 的 `finally` 里显式 `close_all()`（不关会被 aiosqlite 线程吊住解释器，C2 那轮的收官教训）。
   - `tests/s8_frontend_contract.py` 加 **t14**（两侧同判：路由 ↔ 消费者、`CheckpointHead`
     字段集 runner==fe 且不含 state、`before=before` 与 `limit+1` 的形状、界面 tab/点开/
     按码分流/换场清游标），该文件 13 → **14 组**。
5. 契约：路由总表 24 → **26 条**、§3 加 `CheckpointHead` 形状与"为什么没有 state"、
   §6 门禁表补 t13/t14 两行。

  是第四件新面，本批不做。
- 老会话（`_ensure_graph` 重建不出来的那些）在界面上是一行 `reason`，没做"为什么重建不出来"的展开。
