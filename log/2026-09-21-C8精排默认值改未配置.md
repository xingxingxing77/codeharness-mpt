# 2026-09-21 C8 精排默认值改成「未配置」+ 顺手发现 C4 的 t31 是空转门禁（本会话第 3 项）

会话标记 `stage-dev-B2-closeout-20260921-0914`。本会话第 3 项（第 1 项 B2、第 2 项 C2 各有一份日志）。
cursor 从 C2 落到 C8 的理由登记在队列：§7 排在 C8 前的 **C3/C4 判据都要 Qdrant**，本机 09:47 实测未起。

## 1 · 现象

`codeharness/memory/longterm.py:72-89 _rerank()` 每次召回都要走一遍：构造 `httpx.AsyncClient(timeout=20)`
→ POST `http://localhost:9998/v1/rerank` → 连不上 → 被 `:86 except Exception` 吞掉 → 打一条
`精排不可用，已降级为仅粗排…` warning → 返回粗排原序。

判空守卫在 `:76`：`if not settings.reranker.base_url or not texts: return hits[:k]` —— **只挡「URL 为空」**，
而 `configs/settings.py:28` 的缺省值偏偏是**非空**的 `http://localhost:9998/v1`。

## 2 · 排查过程（实际命令与输出）

**① 先确认这个默认值在本机与部署里到底有没有对应服务。**

```
grep -in "rerank\|9998" .env                 → 零命中
grep -rn "9998\|rerank" docker-compose.yml    → 零命中（只有 docs 里提到）
```
→ 缺省指向的是一个**任何地方都不存在**的服务。`docs/README.md:141` 也早写着「reranker 仍离线（未部署）」。
`docs/对照2-记忆管理.md §四-3` 更直接把这条定性成缺陷：**「默认值就是永远先失败一次」**，末尾写「本轮未触碰」。

**② 读 `_rerank` 确认走的是哪条分支。** `:76` 判据是 URL 空不空，非空就无条件发请求，
异常由 `:86` 的宽 `except Exception` 兜住 → 这就是「先抛再吞」（不是慢，localhost 拒连很快，
代价是**每次召回一条 warning + 一次无意义网络往返**，以及把「精排长期缺席」这件事变成噪声而非信号）。

**③ 改法二选一，选最小的。**
- (a) 缺省改成空串 → 既有判空守卫**从此真的生效**；要精排的人显式设 `RERANKER__BASE_URL`。
- (b) 加一次可用性探测（TCP 连一下 / 缓存失败状态）→ 更多代码、更多状态。

判据原文就是「**默认值判空即跳过**（不再抛再吞）」，即 (a)。一行改动的正解，不做 (b)。

**④ 写门禁时先查有没有现成的。** `s5` 里已经有 **t28**（`t28_ltm_rerank_absorbed_and_degrades`），
它显式把 `base_url` 设成 `http://127.0.0.1:1` 钉「配了但离线 → 降级 + warning 留痕」。
所以缺的正是**另一半**：未配置时的干净跳过。新增 `t32_rerank_unset_default_skips_cleanly`，与 t28 成对。

**⑤ 反向验证 t32 不是空转门禁**（`log/c8_probe_t32.py`）：

```
LAYER1=CAUGHT 缺省又指向了一个可能存在的服务：'http://localhost:9998/v1'——未配置就该是空串，精排是…
LAYER2=老状态下 warned=1 条 -> t32 的 assert not warned 会红
```
层① 把配置类默认值填回旧值 → 红。层② 把运行态模拟成 C8 之前（URL 非空）→ **恰好 1 条 warning**，
`assert not warned` 会红；同时这也**实证了哨兵异常被 `except Exception` 吞掉**（它没冒出来，只留下 warning），
也就是「先抛再吞」这件事本身的直接证据。

**⑥ 顺手发现另一件事（不属于本项，已回写 C4）**：读 `s5`  checks 列表时看到
`t31_exp_tenant_isolation`——PLAN 的 C4 说「正向门禁还缺」，实际**门禁已经存在**，
但它内部是这么写的：

```python
class MemStore:
    async def search(self, tag, q, k=2):
        return [r for r in [] ]   # 关键：跨用户永远查不到（B 的行集与 A 隔离）
```
`search` **无条件返回空表**，连 A 自己都查不到 → 「A 写 B 查不到」这句是空转，
真正被断言的只有「两个 manager 实例不同 + 行集不共享」。**没有拿它冒充 C4 已收口**，
而是把这条发现与「下一轮该怎么做才测到生产代码」一起写进 PLAN 的 C4 行。

## 3 · 根因

配置缺省值写成了一个「本机/部署里不存在的服务地址」，而降级判据只看「有没有配」——
两者合起来使**默认状态 = 每次都走失败路径**。属于典型的「默认值替用户做了个没通知他的决定」。

## 4 · 解决方案

- `configs/settings.py`：`RerankerConfig.base_url` 缺省 `"http://localhost:9998/v1"` → `""`，
  注释写明精排是**显式 opt-in**、要启用设 `RERANKER__BASE_URL`，并指回 `对照2 §四-3` 与两条分支的门禁。
- `tests/s5_memory_rag.py`：新增 **t32**（两层判据：配置类默认值 + 用「一碰就抛」的哨兵客户端和 warning 捕获
  证明走的是跳过分支），注册进 `checks` → 现 **32 组**。
- 文档回写：`docs/README.md` §仍未闭合 #2（改成「已改显式 opt-in」并写清两条分支各由哪个门禁钉）、
  `docs/对照2-记忆管理.md` §结论-3 + §三对账表（顺带更正两处已漂行号：`_rerank` 在 `longterm.py:72`，
  文档旧写 `:101` 与 `:97-114`）。
- **顺带补 C2 漏改的一行**：`docs/README.md` #4 仍写「s7 t10 配了静默 + Message/Document 原样回读」，
  与 C2 改后的 t10（白名单只剩 Message 系、**Document 照旧告警**）**语义相反** —— 见 §5「自己引入的问题」。

**断言打在哪**：t32 层② 打在**实际走的分支**上（哨兵客户端没被构造 + 没有 warning），
不是打在构造参数上；层① 打在配置类的**默认值**上而非本机 live 值，这样别人 `.env` 里配了精排也不会把门禁搞红。

**不是代码问题**：`s5` 那 6 处 `跳过（无 Qdrant）` 是外部服务缺失的**设计内探活跳过**，
不是失败，也不该由本项负责（要拿那半边读数得先起 Qdrant，已作为独立授权登记在队列 `blocked:` 第二条）。
