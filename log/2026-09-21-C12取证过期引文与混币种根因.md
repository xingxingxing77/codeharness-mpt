## 段 3 · 根因

1. **「`tests/s7_platform.py:237` 措辞"原料就位"」= 过期引文，不是臆造**。该措辞由 `187b3fc` 引入，
   在 **B11 `4849e32`（09-21 03:31，给 `TraceStore.record` 加 MAX_SPANS 裁剪）** 时被改成裁剪断言文案；
   9 份历史门禁输出仍印着旧文案，所以账面当初引它是真引到了东西，**只是引的行号与措辞都已随 `4849e32` 过期**。
   → 现值可引锚点：`tests/s7_platform.py:241 async def t7_trace_spans()`、`:262 _ok("t7", …)`。
2. **`token_costs.py:12` 的「前端 "$已用"」过期**：B 阶段前端重构后展示层是 **`¥`**（三处），符号已经反了。
3. **跨币种这半的真正根因比账面更硬**：账面写「测试只用单一 gpt-4o」= 缺覆盖；实测是
   **`TOKEN_COSTS` 一张表里混着两种币种**（`:14` qwen3.8-flash 人民币/千、其余美元/千），
   `CostManager.total_cost`（`cost.py:26`）是**无单位 float**，`:40` 把两种单位的数直接相加，
   而消费侧同时存在两个货币标签（日志 `$` @ `cost.py:41`、界面 `¥` @ 前端三处）。
   → 这是记账口径问题，不是补一条测试能了结的。**判据落点因此从「补测试」变成「先定口径」。**
4. **P95 这半账面写大了**：`GET /api/sessions/{sid}/trace` 与前端 trace 展示**都已在位**，
   span 里带 `t0`/`ft`/`ts`（耗时可导），唯一缺的是**聚合口径本身**。不是「三件新面」，是「一个计算 + 一处展示」。
   实现约束：`t0`/`ft` **可为 null**（`runner.py:389-391` 明写采不到就 null、前端宁可不显示也不摆假 0）→
   聚合必须先剔除缺失样本，否则 P95 会被 null 拉歪。

- **C12 不起**（窗口不足 + 改动面吃 s1..s6+s7），本轮**零代码改动**。落三件账面动作：

  把跨币种根因写成「同表混币种相加」）；② `PLAN §9` 新增 C12 待答条目（两条腿：A 分桶不换算 / B 定汇率）；
  ③ 队列 `next_run_hint`/`last_result` 换成复核过的锚点与真读数。
