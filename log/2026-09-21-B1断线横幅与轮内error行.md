### 2.3 横幅的第一版实现是错的，被活体读数当场抓出来

我先按「不另立布尔」的直觉写成从原生状态派生：

```ts
reconnecting(state): boolean { const src = state.evtSource; return !!src && src.readyState !== 1 }
```
在内置面板上实测（后端**活着**）：`bannerPresent=true`，而且**再也不消失**。根因不是 CSS、不是状态没写：
`EventSource` 实例不是 plain object，Vue 的 `reactive()` 按 `getTargetType` 判它 INVALID → 不 proxy，
`readyState` 变了不触发依赖；computed 的依赖只剩「`evtSource` 被赋值」这一次，
于是它把首屏那次 CONNECTING（readyState=0）的值**永久缓存**了。
改成三态 `stream: 'idle' | 'open' | 'down'`（`onopen→open`、`onerror→down`、`resetStream→idle`），
`connected` 一并删掉（同一事实的两份记账，且它本来就零消费者）。

### 2.4 面板不可见时的读数是环境噪声，不是代码洞

同一条 `.errRow` 在内置面板里量到 `cols=10px 0px`、`flowW=64`、`scroll=0x0`——

杀进程与重启放另一条后台命令（`log/b1_kill_restart.sh <杀前等多久> <停多久>`，
只动 8721 那个自起隔离实例，共享 8718 本轮没起）。于是「断→现→恢复→自清」一趟取全。

## 段 3 · 根因

- 横幅：状态源缺失（`connected` 有值无消费者）+ **我第一版把非响应式的 DOM 对象属性当响应式依赖**。
- 红点行：后端信号一直是有的（`server/runner.py:326` `kind="error"`，value=`format_exc(limit=6)`），
  缺的是前端把它摊成一条**轮内**行；台账那份（`logs`）不是它的替代，两处都要在。
- max-tokens：不是「前端漏画」，是**信号没进事件流**——`finish_reason` 停在网关返回值里。
  施工5:575 把它和断线横幅并列进「档三·纯前端就能做，没有任何借口」是**归错档**，它属档二（要先补后端）。

## 段 4 · 解决方案（做了什么）

1. `stores/sessions.ts`：`connected: false` → `stream: 'idle' as 'idle'|'open'|'down'`（三笔写位改完），
   注释写明「别改回 readyState 派生」与实测依据；`ponytail:` 记下天花板——服务端回不可重试状态码
   （如鉴权 401）时 EventSource 进 CLOSED、浏览器不再重连，横幅会停在「正在重连」；升级路径才是
   施工5 F4 判「不做」的自造退避包装器。
2. `App.vue`：`v-if="store.stream === 'down'"` 的 fixed 顶条，几何与配色**逐条照** `ConnectionBanner.module.css`
   （`--dsw-alias-state-error-primary` / `--dsw-alias-label-primary-foreground` 两个 alias 本仓都有，未新增 token）。
3. `stores/sessions.ts` `applyEvent` 的 error 分支：台账那份照旧 push，另外**走块管线**建一块
   `type='Error'`、`closed=true`、`lines=traceback.split('\n')` 的块（键 = `ev.uuid || e<cursor>`）。
   为什么走块管线：顺序、按游标去重、历史回放、`mergeEarlierPage` 的整页往前拼全已经在
   `applyEvent`/`buildRows` 里，另开一份 `errors[]` 就是第二个游标——SSE seq 精度丢事件那条洞同族。
   `closed=true` 不是可选项：`buildRows` 只给「末块已收口」的轮发尾行。
4. `ChatNode.vue`：`type === 'Error'` 显式分支（红点 + 「本轮运行失败」+ traceback 末行），
   样式照 `.turnErrorRow` 家族；源里第三列 `auto` 是放错误码的（`.turnErrorCode`），本仓 error 事件不带码，
   所以只留两轨。行根带 `data-chat-anchor-key`（语义钩子契约 v1.0 要求每条消息根都有，第一版漏了）。
5. `tests/s8_frontend_contract.py` 新增 **t12**：横幅唯一状态源=三态（并**禁** readyState/connected 两种写法）、
   fixed 顶条源值、error 走块管线（type/closed/入序/台账并存）、ChatNode 显式分支、`.errRow` 三条源值。
   动机是 t1 的盲区：`'Error'` 不是 `BlockType`，删掉那条分支 t1 查不出来。
6. **max-tokens 不在本批做**（见段 5「不是代码问题」那栏的归档结论），登记成 PLAN 新项 **B8**。

## 段 6 · 顺手发现（未改，只登记）

## 段 7 · 本轮新踩到的环境坑（同步进队列「环境铁律」）

1. **`EventSource` 实例放进 pinia state 不等于响应式**：Vue 的 `getTargetType` 只认
   Object/Array/Map/Set/WeakMap/WeakSet，其余（含 `EventSource`）判 INVALID 不 proxy →
   从它的 `readyState` 派生 computed，依赖只有「被赋值那一次」，值会永久停在首帧。
   要按连接状态渲染，就得在 `onopen`/`onerror` 回调里写 store 字段。
2. **内置浏览器面板不可见时布局是 0 宽**（`flowW=64`、grid 第二轨 `0px`、`.scroller 0x0`）：
   DOM 存在性可以在面板上读，**几何/源值类判据必须走 `frontend/scripts/shot.mjs --width --height`**。
3. **跨时间的活体读数**：`shot.mjs --eval` 里可以 `await` 轮询几十秒，杀进程/重启放另一条后台命令
   （`log/b1_kill_restart.sh <杀前等多久> <停多久>`），一趟就能同时拿到「出现」和「自清」。
   端口/进程一律 `netstat -ano | grep ':8721 '` 现证 PID，别沿用上一轮的 PID 数字。
4. **反向验证的锚点必须唯一**：`b.closed = true` 在 `sessions.ts` 里有两处（report 的 `end_marker`
   与 error 分支），`replace(..., count=1)` 打中前者 → 出现「拆了断言 t12 仍绿」的**假空转**结论。
   反向验证自己也要有阳性对照：锚点不在就先 `assert old in src`（脚本里已加）。
5. `taskkill` 的中文成功提示在 GBK 终端里是乱码，判据看 `netstat` 那一行与时间戳，别看它的输出。
