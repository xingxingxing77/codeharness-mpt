# 2026-09-21 17:5x · E 项：B10 的 413 与 B7 的 truncated 走到界面上（治理 §3 第 2 条）

阶段三那两轮只落了服务端：`/workspace/file` 加了 5MiB 上限回 413、`import_repo` 加了
`MAX_IMPORT_NODES=20_000` 与 `truncated` 标记，**两个信号前端一个都没接**。
计划原文的改动点本来就写了「前端对 413 展示"文件过大"即可」，所以这是欠账不是新需求。

## 段 1 · 现象

1. **点开一个大文件**：只有一条两秒半就自己消失的红色 toast（内容是后端原文，所以文案不算错），
   预览面板**什么都没留**。用户看到的是"我点了一下，什么也没发生"。
2. **导入一个撞上限的目录**：`已导入 20001 节点 / 20000 边` 绿色成功条——
   与一次完整导入**长得一模一样**。`truncated=true` 全仓零消费者
   （`grep truncated frontend/src` 只命中 `StatsLine.vue` 里 CSS 溢出的那个不相干同名局部变量）。
   后果是关系图不完整而没人知道，N6/下游 RAG 拿到的就是前 20000 个节点。

## 段 2 · 排查过程

1. 先确认后端两个信号确实**在响应里**（不然后端没回，前端无从接）：
   `server/api/workspace.py` 的 `file()` 在 `stat().st_size > MAX_PREVIEW_BYTES` 时
   先 413 再谈读（`:51-56`，读字节在 `:57`）；`import_repo` 路由
   `return await ImportRepo(...)._call(...)` **原样透传** action 的 dict，`truncated` 就在里面。
2. 界面上要分流 413，得先拿到状态码——而 `client.ts::req()` 抛的是
   `new Error(flattenDetail(detail))`，**状态码在这一步被丢了**。
   唯一的替代方案是让调用方去猜 message 里有没有「超过预览上限」这几个字，
   那是把契约写在文案上（后端改一句话界面就退化），不取。
   → 给抛出的 Error 挂 `status`，一处改动，所有调用方都能按码分流。
3. 阈值不在前端重抄：后端 detail 已经带了真实大小与上限（「文件 6.0MB 超过预览上限 5MB…」），
   前端再写一份 "5MB" 就是第二处记账（s8 t13 直接把这条钉成断言）。

## 段 3 · 根因

`req()` 的错误信封只有 message 一个通道，状态信息在出口被压扁；
于是"需要按状态分流"的那类响应（413）只能退化成通用报错，而"需要按标记改语气"的那类响应
（`truncated`）压根没人读。两处都是**信号在最后一米断了**，不是后端缺字段。

## 段 4 · 解决方案

1. `frontend/src/api/client.ts`：`req()` 非 2xx 分支改成
   `const err = new Error(flattenDetail(detail)); err.status = rsp.status; throw err`。
2. `frontend/src/components/DetailsPanel.vue`：
   - `openFile()` 的 catch 按 `status === 413` 分流 → 预览面板里落一句话（`kind:'code'`，
     文本用后端原文）+ warn 语气 toast；其余仍是 error 语气。
   - `doImport()` 的成功分支读 `r.truncated` → 文案补「（目录过大，扫描在上限处截断，图不完整）」，
     语气从 success 换成 warn。
3. 门禁 `tests/s8_frontend_contract.py::t13`（S8 从 12 组到 **13 组**）**两侧同判**：
   后端仍回这两个信号（413 分支在 `read_text` 之前、action 的 `truncated` 键与上限常量在位）→
   `req()` 挂了 status → 前端按状态码分流且在预览里留话 → 前端**没有**把阈值抄成第二份数字。
   少任何一边这格都该红。顺带把 s8 收官打印从硬编码 `12/12` 改成 `len(checks)`
   （同一类"账面与代码漂"的坑，s19 那轮刚踩过一次）。

  没 `FLUSHDB` 是因为另一条会话也可能在用 db15，删别人的样本比留 5 条垃圾更糟。
