# 2026-09-21 18:5x · A4 真模型审批链验收卡在云端 401（未解决）

项号 `A4`（`plan/PLAN.md` §2）。18:3x 用户拍板走 StepFun 云端、验收深度到「批准 → 真执行」，
并给了 `step-3.5-flash` 的单价与一把 key。**跑到第一步就被端点拒收，三格判据一格都没取到。**

## 现象

- 起隔离实例（8721 + `REDIS__DB=15`，`LLM__BASE_URL=https://api.stepfun.com/v1`、
  `LLM__MODEL=step-3.5-flash`、`LLM__API_KEY=<key>` 只走这一条命令的 env）→
  `/api/health` 正常：`{"ok":true,"model":"step-3.5-flash","base_url":"https://api.stepfun.com/v1","api_key_masked":"c5d9c4...e889","auth_enabled":false}`
  —— 说明配置读进来了，不是 settings  precedence 的问题。
- 经 `LLMGateway.aask()` 发一次最小调用 → `openai.AuthenticationError: Error code: 401 -
  {'error': {'message': 'Incorrect API key provided', 'type': 'invalid_api_key'}}`。
- 花钱情况：**0**。401 在计费之前就返回，两次探测都没产生 token 消费。

## 已排除的原因（含实测命令与输出）

1. **「是不是我们网关把凭据发错了」**（本仓历史上有过同类：`api_key` 没进 `ChatOpenAI`、
   `SecretStr` 空值冒充已配）→ **排除**。绕开整条自研链路，最原始地打：
   ```
   POST https://api.stepfun.com/v1/chat/completions
   Authorization: Bearer <同一把 key>        # urllib 直连，不经 codeharness/provider/*
   {"model":"step-3.5-flash","messages":[{"role":"user","content":"回复 OK"}],"max_tokens":4}
   ```
   输出：`HTTP 401 {"error":{"message":"Incorrect API key provided","type":"invalid_api_key"}}`。
   裸调用同形失败 ⇒ 服务端拒绝的是凭据本身，与我们的实现无关。
2. **「是不是 base_url 写错了少了一段路径」**→ **排除**。同一把 key 换 `https://api.stepfun.com/step-1/v1`
   → `HTTP 404`（路径不存在，不是鉴权话术）；`/v1` 那支回的是明确的 `invalid_api_key`。
   也就是「能到、但凭据不被认」，而另一个候选路径根本不存在。
3. **「key 被我读错/截断/被 shell 吃掉一段」**→ **排除**。落盘文件 `32` 字节，
   脚本打印指纹 `长度=32 前6=c5d9c4 后4=e889`，与 `/api/health` 自己 mask 出来的
   `c5d9c4...e889` 一致（两处独立取值）。
4. **「是不是 `.env` 里那把 `LLM__API_KEY=ollama` 赢了 env」**（pydantic-settings 的 dotenv 与 env 优先级）
   → **排除**。`/api/health` 回的 `model`/`base_url` 都是我在命令行 env 上设的值，
   mask 出的指纹也是新 key 的，说明 env 优先这条在本机成立（与 PLAN §9 记的同一条）。
5. **「模型名不存在导致鉴权先失败」**→ **排除**。StepFun 对未知模型回的是模型类错误，
   这次回的是 `invalid_api_key`；且 `step-3.5-flash` 是用户本条消息里亲口给的型号。

## 当前最可能的怀疑

按可能性排：

1. **key 已被轮换/吊销或过期**。`plan/PLAN.md` §9 记着 15:2x 这把端点**曾经过**
   （`log/b14_stepfun_gateway.out`：裸 API 回 `finish_reason=tool_calls`、走自家网关 `aask()` 真回 `'OK'`）；
   同一把 key 今天 18:5x 被拒 → 中间变了的是账号侧状态，不是本仓代码（本仓这九十分钟里
   改动面在计量/runner/前端，`codeharness/provider/gateway.py` 一行未动）。
2. **额度或套餐状态**。`32` 位 key 的形态没变。
3. **key 属于另一个 host 面**（StepFun 有开放平台/火山式两套端点的话）。裸调用那条 401 话术
   写得就是鉴权，不像路由错，所以这条排在最后。
