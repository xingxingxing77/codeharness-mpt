# 2026-09-21 · C10：把「登录态不跨 worker」写进接口契约（顺带查出鉴权开关名是错的）

> 冷会话 `stage-dev-cold-20260921-1006` 第 2 项。PLAN §4 C10 判据二选一：
> **要么多 worker 下登录态可用，要么把「不跨 worker」写进契约并停止当 bug 追** → 本轮走**第二支**。
> 改动面 `docs/**` + `server/auth.py`（两处都是文件头/文档措辞，无行为变化）→ 按 §0.3 跑了 s8 + s7 双配置。

## 段 1 · 现象

账面（PLAN C10 行）说：`server/auth.py` 的 `_Tokens` 是进程内单例、ceiling 文件头自述，而
`docs/前端/接口契约.md` 的 §5 只写了「SSE 只能走 `?access_token=`」那半句，
`grep worker|多进程|跨进程` 在契约里零命中 → 缺一整段边界说明。

## 段 2 · 排查过程（含实跑命令）

1. **先按 §0.6 复核行号**（PLAN 的锚点是 09-20 取的）：`_Tokens` 实际在 `auth.py:111-136`（不是账面 `:64-89`），
   SSE 兜底在 `:152`（不是 `:100-105`），ceiling 自述在 `:7-8`。**又漂一次**——这条已有教训，引用前必 grep。
2. **读完整 `server/auth.py` 后才看到同族还有两条**（账面只记了 token 那一条）：
   - `_login_fails` 登录失败限速（`:69-108`）也是进程内字典 → 多 worker 下「5 次/60s」实际变 5×N；
   - `users.json` 的读-改-写串行靠 `_USERS_LOCK = threading.Lock()`（`:27`）——**线程锁不互斥进程**，
     `_save_users`（`:36-40`）虽是 `tmp.replace` 原子换文件，那只防撕裂写、**不防 lost update**：
     两 worker 各 load 旧表各 save，后写的把先写的账号抹掉。
3. **开关名对不对，实测**（这一步改变了本项的性质）：`auth.py:3` 与契约 §5 都写 `PLATFORM__AUTH`。
   `configs/settings.py:114` 是 `env_nested_delimiter="__"`、无 `env_prefix`，`PlatformConfig` 嵌在顶层
   `Settings` 里 → 段名必须等于字段名 `auth_enabled`。两个名字各起一次进程读现值：
   ```
   PLATFORM__AUTH=1          → settings.platform.auth_enabled = False
   PLATFORM__AUTH_ENABLED=1  → settings.platform.auth_enabled = True
   ```
   **文档写的那个开关名根本打不开鉴权。** 后果不是「不方便」而是**反的安全语义**：
   运维照文档写 `PLATFORM__AUTH=1`，`auth_enabled` 仍是 False → `current_user` 恒返回 `"default"`
   （`auth.py:149-150`），全站不校验、user 隔离整个不生效，而他以为开了。
4. **为什么「不跨 worker」今天打不到**（判据第二支成立的前提，得证）：
   `docker-compose.yml:31` = `uvicorn server.app:app --host 0.0.0.0 --port 8000 --workers 1`（**钉死单 worker**）；
   compose 的 environment 块（`:25-30`）只有 Qdrant/Redis 那几项，**没设 auth**；本机 `.env` `grep AUTH` 零命中；
   `settings.py:97` 默认 `False`。→ 要踩到这条边界得**同时**翻两个非默认开关。
5. **多 worker 不是没验过，但鉴权面不在覆盖里**：`docs/施工4:65` 记了 `--workers 2` + redis 的真进程冒烟
   （/graph、/trace、/events/history 跨 worker 正常、seq 用 stream 编码），那一轮没开 auth。
   顺带发现 `施工4:21` 写的 `server/runner.py:25 graphs[sid]` 行号已漂（现 `:132`、`:348`；`:25` 现在是 `CostManager()`）——
   我在契约里引用时用的是现取锚点并注明那里已漂。
6. **跑门禁前的只读预检**（8718 没起，不能用 `curl /api/sessions`）：Redis 索引 **609** 条，
   `{created:501, stopped:77, finished:17, failed:14}` → **零 running、零 awaiting_human**，`heal_running()` 是 no-op。

## 段 3 · 根因

契约文档缺的不是那一句 SSE，而是**整个「进程内状态 × 部署形态」的边界段**：auth 的实现选择（内存 token 表 +
文件用户表 + 线程锁）本身是有意的 ponytail 简化且文件里写了，但**没有任何一处面向使用者的文档说过
「所以部署只能是单 worker」**，于是每一轮都会把它当新 bug 重新发现一遍（PLAN 里它就是一行 ⬜）。
而开关名的错，是「文件头注释」与「settings 实现」两条线各写各的、中间没有断言钉住导致的漂移。

## 段 4 · 解决方案

1. **`docs/前端/接口契约.md` §5 重写 + 新增 §5.1**：① 开关写成真名 `PLATFORM__AUTH_ENABLED`，
   并把「`PLATFORM__AUTH=1` 打不开」这条实测连同原因（`env_nested_delimiter` 段名=字段名）写在同一行防复发；
   ② §5.1 一张四行边界表（token 表 / 失败计数 / users.json 读-改-写 / 重启失效），每行给**落点行号 + 多 worker 后果 + 升级路径**；
   ③ 写明「为什么今天打不到」（compose 钉 `--workers 1` + auth 默认关 + `.env` 未设）与
   「提 `--workers` 之前必须先做完升级」；④ 明确**按边界对待，别再当 bug 排查**——这就是判据第二支要求的「停止当 bug 追」。
2. **`server/auth.py` 文件头两处更正**（纯注释、无行为变化）：开关名改真名并留一句 ⚠；
   ceiling 那一条从「只坦白 token」补成三条同族 + 指向契约 §5.1。
   **没做的**：不加 `validation_alias` 让 `PLATFORM__AUTH` 也能用——那是给一个错名字建兼容层，
   且会掩盖「文档曾写错」这件事；改文档是真名不对症的更小解法。
3. **按判据改状态，不偷偷当已修**：C10 记 ✅ 的含义是**「写进契约 + 停止当 bug 追」这一支已满足**，
   多 worker 下登录态**仍然不可用**——契约与 PLAN 行里都写死了这句，避免下一棒误读成「修好了」。

## 段 7 · 释锁后回来补的一格实测（10:58，把「读实现所得」变成真读数）

释锁后本会话没退出，用剩余窗口把 C10 边界表里那条**最关键**的断言跑成了实测。
手法：`TestClient` 把 auth 路由单独挂起来，**用两个独立进程模拟两个 worker**（多 worker 部署的真实形态就是多进程），
不起端口、不碰共享 Redis db=0、`USERS_FILE` 指到 `log/c10_probe_users.json`（不污染 `server/data/users.json`）。

| 断言（此前只有「读实现」） | 实测读数 |
|---|---|
| 票不跨进程 | 进程 A `register=200` → `Bearer /me=200 {'user':'probe_a'}`；**同一张票在进程 B → 401「登录已过期」** |
| 账号表是共享的（不对称才是本条边界的形状） | 同一口令在 B `login=200`，B 自签的票 `Bearer /me=200` → **文件共享、内存表不共享** |
| SSE 走查询参数与 Bearer 等价 | A `GET /api/auth/me?access_token=<tok>` → **200**；无票 → 401；错密码 → 401 |
| 失败计数是进程内的（多 worker 下阈值 5×N） | 连打 7 次错密码 → `[401,401,401,401,401,429,429]`，第 6 次起 429，`_LOGIN_MAX_FAILS=5`/`_LOGIN_WINDOW=60` 均现取 |

读数落盘 `log/c10_probe_A.out`、`log/c10_probe_B.out`、`log/c10_probe_C.out`（三笔 exit 0），脚本
`log/c10_probe_authproc.py`（按惯例不入库）。契约 §5.1 已把这段实测写进去。
**仍然没验的**：真正的 `uvicorn --workers 2` + nginx 轮询那条端到端路径（要起服务，缺用户授权），
以及 users.json 跨进程 lost update（那要真并发两笔注册才炸，本轮只有单进程读）。
